## 概要

- 銘柄コードを入力して、価格チャート・テクニカル指標・将来予測を表示
- **7モデルのアンサンブル**による確率的価格予測（ファンチャート）
- 全ペインが時間軸を共有。価格 / RSI / MACD のタイミングを縦位置で照合可能
- 予測区間はシアンの縦点線より右に表示
- **PIT再現モード**で過去の任意時点に巻き戻し、「当時の目線」で指標・予測を再現

> 本予測は統計的推定であり、投資判断はご自身の責任で行ってください。

## 予測エンジン Mirage Ensemble+

7つの独立モデルを重み付き合成して、ステップ先の価格分布を生成する。

| ID | モデル | 重み | 内容 |
|----|--------|------|------|
| M1 | ブートストラップMC | 0.19 | 実リターン分布を再標本化したモンテカルロ（2500シミュレーション） |
| M2 | パターン類似 kNN | 0.24 | 直近の値動きに類似した過去局面（k=25）の其後を集計 |
| M3 | ARMA自動選定 | 0.08 | (p,q)∈{0..3}²のグリッドサーチでAIC最小モデルを選定。レジーム推定付き |
| M4 | テクニカル | 0.16 | RSI・MACD・BB等のスコアリング |
| M5 | ニュースKW | 0.12 | ニュース見出しのポジ/ネガ・キーワード集計（各22語） |
| M6 | マクロ相関 | 0.09 | 夜間FX・指数との相関 β（日本株のみ） |
| M7 | パターンスコア | 0.12 | ローソク足パターン（61種）の時系列重み付きスコアリング |

出力は中央値パス（実線）＋ 68% / 90% 信頼帯（ファン）。

### モデルの性質分類

| 性質 | モデル | 重み合計 |
|------|--------|---------|
| 統計・確率 | M1・M2・M3 | 0.51 |
| テクニカル | M4・M7 | 0.28 |
| センチメント | M5 | 0.12 |
| マクロ | M6 | 0.09 |

### M3：ARMA自動選定（旧：AR(1)）

- 対数収益率列を入力とし、(p,q)∈{0,1,2,3}² の16候補をCSS（条件付き最小二乗）で推定
- AIC最小モデルを採用。データが少ない場合（60本未満）は無効化
- レジーム判定：AR(1)係数 φ₁ に基づきモメンタム / 平均回帰 / ランダム的 を表示
- 予測詳細に選定次数・AIC値・係数を表示

### M7：ローソク足パターンスコアリング（新規）

- 61種のローソク足パターンを検出し、時系列重み付きスコアを算出
- スコア = Σ dir × グループ重み × 時系列重み
  - グループ重み：酒田1.0 / 3本組0.7 / 継続0.6 / 2本組0.5 / 窓0.4 / 単体0.2
  - 時系列重み：直近ほど重く線形減衰（0本前=1.0 → 14本前=0.0）
- スコアをロジスティック関数で上昇確率に変換
- チャート上の矢印表示（`detectPatterns()`）とは独立した別処理

## ボラティリティ推定：GARCH(1,1)

ファンチャートの幅（信頼帯）を決めるボラティリティ推定に **GARCH(1,1)** を採用。

```
σ²_t = ω + α·r²_{t-1} + β·σ²_{t-1}
```

- パラメータ (ω, α, β) を座標降下法による対数尤度最大化で推定
- 安定条件 α + β < 1 を維持（持続性パラメータとして表示）
- 翌期予測 σ²_{T+1} = ω + α·r²_T + β·σ²_T をファン幅に使用
- データ不足（40本未満）の場合は全期間標準偏差にフォールバック

従来のEWMA固定補正（λ=0.94, ×1.35）から置き換えることで、相場環境の変化に
動的に対応したファン幅を実現する。持続性（α+β）は実効ボラ表示欄に付記される。

## ローソク足パターン認識

日本伝統の酒田五法と西洋テクニカル分析を統合した **61パターン** を検出する。

| グループ | 件数 | 例 |
|---------|------|----|
| 単体 | 14 | 大陽線、ハンマー、十字線、トンボ 等 |
| 2本組 | 12 | 陽の包み足、切り込み線、黒雲 等 |
| 3本組 | 12 | 明けの明星、赤三兵、三羽烏 等 |
| 継続 | 8 | 上げ三法、持ち合い放れ 等 |
| 窓 | 12 | ブレイクアウェイG、ランナウェイG、アイランドリバーサル 等 |
| 酒田 | 3 | 三山、三尊天井、逆三尊 |

検出結果は2つの用途で使用される：

- **チャート矢印表示**：各バーにパターン名と方向を表示（強気↑ / 弱気↓ / 中立→）
- **M7スコアリング**：直近14本以内のパターンをアンサンブルの入力として使用

## テクニカル指標

| 指標 | 計算方式 | 備考 |
|------|---------|------|
| ローソク足 | OHLC | — |
| ボリンジャーバンド（BB） | 期間n の単純移動平均 ± 1σ / 2σ | 窓方式（直近n本） |
| SMA | 単純移動平均 | — |
| RSI(14) | Wilder平滑化（標準シード：初期14本平均） | 累積方式。70 / 50 / 30 ガイドライン（バッジ判定閾値と統一） |
| MACD | EMA(12) − EMA(26)、シグナル EMA(9) | ヒストグラム＋GX/DXクロスドット |

### BB と RSI/MACD の性質の違い（重要）

- **BB は窓方式**：直近n本だけで計算するため、基準点（右端）が変わると値が動く
- **RSI / MACD は累積方式（EMAベース）**：ある日付の値は過去全体の蓄積で決まる
  - → **同一日付の値は、基準点をどこに置いても不変**（数学的性質）
  - → 変化が現れるのは「各時点の最新値（右端）」や「予測延長部」

この違いが PIT再現モードでの見え方に直結する（後述）。

## 指標オーバーレイ（拡大ビュー）

ミニチャートをタップすると全画面の拡大ビューを表示。

- チップで各指標を ON/OFF
- 価格・RSI・MACD のペインが時間軸を共有
- 予測区間（シアン縦点線より右）に、RSI・MACD を予測価格パスから延長した推定値を同色の淡線で表示
- MACD のクロス点（GX=緑 / DX=赤）は**実測区間のみ**ドット表示
  - 予測区間のもつれによる偽クロスは描画しない

## PIT再現モード

**Point-in-Time（PIT）リプレイ** — 過去の任意の日を「今日」とみなし、その時点で実際に見えていたチャートと予測を再現する機能。

### 目的

「当時どういうチャートで、どう判断したか」を後から振り返る。
当時の指標・予測が、その後の実際の値動きとどうズレたかを検証できる。

### 操作

1. 指標オーバーレイを開く
2. 上部の **PIT再現スライダー** を左に動かす
3. オレンジの縦線が選択日に立ち、その時点を「今」として再計算
4. 右端に戻す、または「解除」で通常モードに復帰

### 動作仕様

| 区間 | 表示内容 |
|------|---------|
| オレンジ縦線より**左**（過去） | 通常表示のまま（同一日付の指標値は基準点に依らず不変＝数学的性質） |
| オレンジ縦線（カーソル位置） | 当時の「最新」。ここから**当時の予測（オレンジ）**を再生成 |
| オレンジ縦線より**右**（未来） | 当時見えなかった実際の値動きを**減光（ゴースト）表示** |

- 当時の予測ファン・RSI/MACD延長線は**オレンジ**で描画され、ゴースト化された実際の値動きと直接対比できる
- 予測1本目は実際の翌足と同じX位置に置かれるため、ズレが縦方向の距離として読める
- 画面下部に**答え合わせ**を自動表示：当時の判定・P↑%・実際のN足後終値・方向的中◯✕・68%/90%帯の内外
- スライダーのドラッグ中は軽量描画し、指が止まってから当時予測を計算（結果はキャッシュされ往復操作は即時）

### 指標ごとの見え方

- **BB**：窓方式のため、カーソル位置の最新バンドが当時の値で再計算され、変化が見える
- **RSI / MACD**：累積方式のため、実測部の波形（同一日付）は変わらない
  - 変化するのは **予測延長部（淡い線）の起点と向き**
  - これが「当時はこう予測した」を表す
- **MACDクロスドット**：実測のクロスのみ。予測区間には出ない

### 精度に関する注意

PIT再現で完全に当時を再現できるのは価格ベースの M1〜M4・M7（重み合計 0.79）。
M5（ニュース）・M6（マクロ相関）は過去データを後から取得できないため、
現在値を流用した近似。トレンドの方向性検証には影響しないが、参考値として扱う。

なお全モデルの乱数はデータ由来シードの決定的乱数（xorshift）を使用しており、
**同一データに対する予測・シグナルは何度再実行しても同一**（MCノイズによる判定フリップなし）。

## データ取得・CORSプロキシ

ブラウザから直接データソースを呼ぶと CORS で拒否されるため、中継プロキシを経由。

- 既定：`corsproxy.io` → `allorigins.win` の順に自動フォールバック
- 安定運用：設定 → CORSプロキシ → カスタム に、自前の Vercel 中継エンドポイントを指定可能
  - 形式：`https://<your-app>.vercel.app/api/proxy?url=`

外部有料サービス・APIキーは未使用。

## PWA / オフライン

- Service Worker は**ネットワーク優先**（GT DASH方式）
  - CSS/JS の変更が即反映されやすい
  - データAPI（オリジン外）はキャッシュしない
- `manifest.json` の `start_url` / `scope` は相対パス（`./`）。サブフォルダ運用に対応
- ホーム画面に追加すると全画面アプリとして起動

## デプロイ

### GitHub Pages

```bash
# 例: yubun241.github.io リポジトリ内に stocksight/ フォルダを作る場合
cd yubun241.github.io
mkdir stocksight
cp index.html manifest.json sw.js icon-*.png stocksight/
git add . && git commit -m "Add StockSight PWA" && git push
```

→ `https://yubun241.github.io/stocksight/` で公開。

### Android（TWA・任意）

GT DASH と同じ bubblewrap フロー。

```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://yubun241.github.io/stocksight/manifest.json
bubblewrap build
# 署名は既存キーストア (~/android.keystore, alias: android) を指定
```

`assetlinks.json` をルートドメイン（`yubun241.github.io/.well-known/`）に追記して
URLバーを消すのも GT DASH と同様。

## 既知の制約

- M5（ニュース）/ M6（マクロ）は過去時点の再取得が不可。PITでは現在値を近似流用
- M3 ARMA自動選定は60本未満のデータでは無効化（nullを返す）
- シグナル走査（▲▼）は速度優先の軽量構成（EWMAボラ・ARMA次数(1,1)上限・M1=400シミュレーション）
- M5の英語キーワードは単語境界一致（例: Commission が miss に誤ヒットしない）。活用形（cuts等）は不検出
- GARCH(1,1)推定は座標降下法による近似MLE。データ40本未満は標準偏差にフォールバック
- 予測は統計的推定。市場環境の急変・イベントリスクは織り込めない
- データソースのAPI仕様変更でニュース取得が変動する可能性あり
